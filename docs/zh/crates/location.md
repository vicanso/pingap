# Pingap Location 模块

本模块为反向代理与 API 网关提供智能、灵活的请求路由。可基于请求主机名与 URL 路径做路由决策，支持强大的匹配选项、URL 改写及其他必要代理能力。

## 功能

- **动态主机匹配**：按 `Host` 头匹配请求：
  - **精确匹配**：如 `example.com`（不区分大小写）
  - **通配 / 后缀**：如 `*.example.com`（只匹配子域名，不含根域名本身）
  - **正则匹配**：如 `~(?<subdomain>.+)\.example\.com`，支持命名捕获。
- **按主机分桶的路由索引**：每个 server 按权重排序的 location 会按精确主机、后缀、正则和"任意主机"建立索引，主机名多样时匹配不必逐个扫描无关 location（见 `LocationHostIndex`）。
- **灵活路径匹配**：按 URL 路径以不同策略匹配：
  - **精确匹配**：如 `=/api/login`
  - **前缀匹配**：如 `/static`
  - **正则匹配**：如 `~/users/(?<id>\d+)`，支持命名捕获。
- **URL 改写**：代理前动态修改请求路径，可替换命名捕获变量。
  - `rewrite = "<正则> <替换>"`；替换里的 `$1`、`$name` 指正则的分组。若 `$name` 是**请求变量**——主机模式的命名捕获，或插件设置的变量——则先替换为该变量的值，例如 `host = "~(?<tenant>.+)\.example\.com"` 配 `rewrite = "^/users/(.*)$ /$tenant/$1"`，`acme.example.com/users/me` 会改写为 `/acme/me`。只写一个带 `$` 的替换（`"/$1"`）表示整段路径替换。请求的查询串会保留：用 `?` 接在后面，替换本身带查询串时用 `&`（`rewrite = "^/old/(.*) /search?from=old&q=$1"` 把 `/old/a?page=2` 改写为 `/search?from=old&q=a&page=2`）。正则编译失败或超过两段的规则，在构建 location 时报错，而不再被静默忽略。
- **匹配条件**：`match_headers`、`match_query`、`match_cookies` 把 location 限定在带有所列内容的请求上，每项写成 `name:value`（值完全相等）或 `name`（存在即可），全部满足才匹配。查询参数的值既按发来的原样比较，带百分号编码时也按解码后的值比较：`match_query = ["v:a+b"]` 对 `?v=a+b` 和 `?v=a%2Bb` 都成立。`+` 就是加号，不当作空格。
- **请求节流**：限制 location 同时处理的最大并发请求数。
- **正文大小限制**：限制客户端请求体最大尺寸，防止滥用。
- **按 location 设置超时**：location 上的 `connection_timeout`、`read_timeout`、`write_timeout` 对这个 location 的请求生效，替代 upstream 上的同名设置。这样同一个 upstream 下，上传路径或长轮询可以等得更久，普通接口等得更短。location 没设的项沿用 upstream 的值。`connection_timeout` 比 upstream 的 `total_connection_timeout` 长时，后者会被一并抬高。超时配成 `0s` 是配置错误。
- **头修改**：转发上游前添加或设置自定义 HTTP 头。
- **gRPC-Web 支持**：无缝代理 gRPC-Web，并翻译为标准 gRPC。
- **可扩展插件**：通过插件系统附加自定义处理逻辑。

## 核心概念

### `Location`

`Location` 是封装完整路由规则集的中心结构。由 `LocationConf` 创建，包含判断入站请求是否匹配以及如何处理的全部逻辑。

### `HostSelector`

请求 `Host` 头的匹配方式：

| 模式 | 含义 |
| --- | --- |
| `example.com` | 精确匹配（不区分大小写） |
| `*.example.com` | `example.com` 的任意子域名（不含根域名本身） |
| `~regex` | 正则，可带命名捕获 |

例如，模式为 `~(?<name>.+)\.npmtrend\.com` 的 `HostSelector` 会匹配 `charts.npmtrend.com`，并把 `charts` 捕获到 `name` 变量。

域名末尾写出根标签（多一个点）时指的仍是同一个域名：`Host: example.com.` 的请求按 `example.com` 匹配，配置里的域名末尾带点时同样会去掉。以前按原样匹配时，这样的请求匹配不到该域名的 location，会落到兜底的 location 上，绕过保护这个域名的插件。

精确与通配模式以小写存储，与请求主机就地比较，因此 `Host: API.Example.COM` 能匹配 `api.example.com`，且不会为每个模式复制一份小写主机名。没有命名分组的正则（主机或路径）只做普通匹配，正则引擎不必跟踪分组位置；只有带 `(?<name>...)` 的模式才付出提取的开销。

### `LocationHostIndex` / `ServerLocationRoute`

在 server 的 location 列表（重新）加载时构建。对每个请求主机，索引返回**按权重排序**的候选列表（精确 + 匹配的后缀 + 所有正则主机 location + 任意主机 location）。完整的路径/条件匹配只对这些候选执行，因此首个命中与对完整权重排序列表做线性扫描的结果相同。每次查找只分配一个小 `Vec`：主机名只在含大写字母时才转小写，几个桶的下标通过排序合并。

### `PathSelector`

该枚举决定如何匹配请求的 URL 路径。匹配策略由配置字符串的特殊前缀决定：

- **`=`（精确匹配）**：路径必须完全相同。如 `=/api/v1/status`。
- **`~`（正则匹配）**：路径与正则匹配。如 `~/api/users/(\d+)`。
  改写规则每个请求只跑一次正则：最左匹配生成新路径，模式有命名分组时，这些分组从同一次匹配变成请求变量。
- **（前缀匹配）**：无前缀时，请求路径须以给定字符串开头。如 `/api/`。

请求按**规范化**后的路径匹配：百分号编码解码一次，去掉路径参数，反斜杠当作斜杠，`.` 和 `..` 路径段被消解，连续的斜杠合并。`/%61dmin/users`、`//admin/users`、`/public/../admin/users` 都会匹配 `/admin` 的 location，和收到它们的上游的理解一致，所以换一种写法绕不开该 location 的插件。没有 `rewrite` 规则改动的请求按原样转发。

`rewrite` 对这种形式同样成立，所以靠改写加前缀或去前缀的规则无法通过换写法绕开：`path = "/users"` 配 `rewrite = "^/users/(.*)$ /acme/$1"` 时，`/%75sers/x` 转发为 `/acme/x`，`/users/a/../../users/y` 转发为 `/acme/y`；以前前者匹配不上规则，后者加上前缀后在下一段又退了出去。只要安全，规则就作用于原始路径，绝大多数请求都是这样：`/users/group%2Fproject` 转发为 `/acme/group%2Fproject`，路径里的 `;jsessionid=...` 和 `//` 都保留。以下情况改为作用于规范化后的路径（URI 不能直接携带的字节重新做百分号编码）：原始路径匹配不上规则而规范化后的匹配得上；路径在任何一种读法下含有 `.` 或 `..` 段（`%2e%2e`、`..;x`、`a%2F..%2Fb`）；或者两种路径改写出的结果不一致。只有这些请求会丢掉被规范化当作语法的部分。规则得到的结果不是合法路径时，请求以 `500` 失败，不会退回按原路径转发。

其中两项只有部分后端会这样解释，匹配时按它们的解释来：

- **路径参数。** Servlet 容器（Tomcat、Jetty）在解析路径之前会去掉路径段里的 `;name=value`，所以对它来说 `/public/..;/admin` 是 `/admin`，`/api;v=1/admin` 是 `/api/admin`，`/login;jsessionid=A1` 是 `/login`。匹配时去掉每个路径段里从 `;` 到段尾的部分。
- **反斜杠。** IIS 把 `\` 当作 `/`，所以 `/public\..\admin` 是 `/admin`。

不这样解释的后端在这类路径上本来就没有内容，所以不受影响。到 0.15.0 为止这两种写法都没有覆盖，前面挂的是这类后端时，可以绕开本该拦在前面的 location。

配置里的精确路径和前缀路径也保存为同样的形式，所以 `/%E6%96%87%E6%A1%A3` 和 `/文档` 指的是同一个 location。正则按原样使用，匹配的是规范化后的路径：模式里要写 `/a b`，不要写 `/a%20b`；路径参数和反斜杠此时已经不在路径里，模式匹配不到它们。配置里精确路径和前缀路径中的 `;` 同样会把路径截断。
- **（任意）**：空路径字符串匹配任意请求路径。
